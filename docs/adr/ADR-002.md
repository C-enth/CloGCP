# ADR-002: Operational local GUI and serialized service access
Date: 2026-10-10. Status: implemented in Sprint 1.

Activate the FastAPI/React/TypeScript/Vite stack already selected in ADR-001. Serve the
compiled frontend from Python package data; Node is needed only for rebuilding/tests.
Use native styled React components rather than another component/state framework.
A single executor serializes all database access and jobs; Store is opened/closed within
that executor. An OS workspace lock prevents another GUI owner. Existing CLI locks and
transactions remain authoritative; analysis does not import transport code.

Browser-selected multipart uploads are bounded and staged under the workspace; no API
accepts server filesystem paths or archives. Existing verifier/import/assess/review/export
functions own semantics. Queued jobs can be cancelled; running synchronous analysis is
not interrupted unsafely. Session bootstrap uses a fragment secret, HttpOnly SameSite
cookie, independent CSRF token, exact loopback Host/Origin and restrictive bundled CSP.
Only bounded redacted normalized observations are inspectable; raw files are not served.

Exceptions/remarks use existing NEEDS_VALIDATION decision notes (explicit exception
prefix), not new approval semantics or schema. JSON register exports supplement existing
openpyxl workbook output. Reports are opaque generated IDs in the approved workspace.
No new datastore, analysis framework, collectors or authorization conclusions.
