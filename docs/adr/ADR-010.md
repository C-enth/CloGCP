# ADR-010: Only collected projects appear in CloSec

Status: Accepted (0.8.4, pilot feedback). Supersedes the organization-wide analysis scope
introduced in 0.7.0.

## Context
Collector 2.2.x searched IAM at the folder and organization of the selected project
(`gcloud asset search-all-iam-policies --scope=organizations/...`). That search returns the
IAM bindings of every project the account can see. CloSec 0.7.0 analyzed all of them, so a
single-project package produced findings, account rows and attack paths naming dozens of
other projects. Analysts read this as mixed-up data, and org-wide collection can exceed a
project-scoped authorization.

## Decision
- At import, IAM search results (`asset_iam_search`, `folder_*_iam_search`,
  `organization_*_iam_search`) are stored only when they belong to the collected project
  (by project ID or number) or to the organization/folders in that project's own parent
  chain. Everything else is dropped before storage and never appears in observations,
  findings, paths, reports or account lists.
- Collector 2.2.3 runs folder/organization IAM searches only with
  `-IncludeOrganizationSearch` and a typed confirmation; the project-scope search, parent
  IAM policies and organization policies are unchanged.
- A project appears in CloSec only when its own collector output is imported. Cross-project
  analysis comes from importing several projects (enterprise assessment).

## Consequences
Single-project packages show only that project. Identities that are themselves evidence on
the collected project's policies (for example a service account from another project bound
there) remain visible, because they describe the collected project's access. Packages
imported before 0.8.4 keep their stored data until deleted and re-imported.

Amendment (collector 2.2.4): `gcloud compute images list` returns Google's public image
projects by default. The collector now passes `--no-standard-images`, and at import the
`images` dataset keeps only images whose `selfLink` names the collected project; public
catalog entries in earlier outputs are dropped before storage under this decision.
