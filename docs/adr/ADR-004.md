# ADR-004: Immutable enterprise assessments and typed relationship projections
Date: 2026-10-10. Status: implementation in Sprint 3.

Retain isolated immutable import runs. Explicitly materialize a derived enterprise run
from selected original runs with SQL unions of canonical facts and all evidence locators.
Copy no raw files; verify original hashes. Preserve contradictory snapshots; do not guess
which collection is authoritative. Do not union page fragments into inventory completeness.
Bound input runs/observations and reject mixed normalization versions rather than select
an arbitrary parser's observation at a shared raw locator. Source package limits remain.

Reuse existing rules, candidates, decisions and Excel engine on the derived run. Persist
additive enterprise relationship/investigation projections in DuckDB. No new datastore or
authorization framework. NetworkX queries operate on bounded filtered edges only; a graph
is not a reachability or exploitation conclusion. Updates create a new explicit snapshot;
ordinary imports do not rebuild the whole graph. Existing snapshots remain reviewable.

IAM edges reuse R1.2 decisions, evaluated separately per partition. S3/KMS/grants, workload,
monitoring, peering/TGW/RAM inputs establish explicit references only. They do not establish
service-specific effective access or traffic inspection. Typed statuses separate references
from supported/blocked authorization. Shared investigations require a common exact resource
anchor plus evidence, not a matching control ID, name or policy text. Analyst review uses
existing append-only evidence-fingerprinted decisions; added evidence requires revalidation.
