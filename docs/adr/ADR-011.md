# ADR-011: Versioned GCP evidence composition and independent report finalization

Status: Implemented candidate; synthetic acceptance required. Requested by the assessor
in the final-workflow integration clarification (2026-10-26).

Opening a compatible workspace must not migrate tables, recover scope transactions,
regenerate assessments or delete historical artifacts. The app checks compatibility with
read-only DuckDB first. Incompatible or interrupted workspaces require an explicit recovery
or a separately versioned upgrade. `storage.side_by_side` makes an explicitly requested
copy and verifies every file and all table rows before permitting its use. Prior releases
and workspaces are retained. No alternate database or framework is introduced.

Attack-path recalculation uses normalized stored evidence and the corrected engine only.
It writes immutable evaluation artifacts outside assessment/review tables, including prior
paths and old/new reconciliation. Repeated evaluations are separate versions. No import,
rule assessment or enterprise snapshot rebuild is part of this action.

Supplementary collector output is a bounded, hashed native import contract. It is first
imported as a distinct immutable run. `evidence.composition` references both source runs,
retains their raw artifacts, and materializes selected observations into a deterministic
new analysis run. Resource-specific later attempts supersede historical policy facts;
failed attempts cannot silently reuse stale success. Older and same-time conflicting
sources remain historical. Collection timestamps and conflicts stay explicit. Mixed dates
cannot establish concurrent attack prerequisites. The original imports, frozen editions,
reports, decisions and SRE history are never updated. Repeated imports/compositions reuse
stable identities. Existing global IAM dependencies require the existing evaluators in the
new run; this is the documented broader-analysis fallback, not a baseline reassessment.
Unchanged finding fingerprints retain their existing evidence-bound review validity;
changed findings require revalidation. No path approval is inherited.

`clogcp_delta` is a separate explicit-execution tool; the application never launches it.
Its allowlisted configuration reads use a reviewed scope plan and matrix hash, bounded
workers, per-API pacing/retries, pagination limits and independent failure statuses. It
cannot grant IAM, enable APIs or read secret values. Missing resource names stay pending.

`clogcp_report_finalizer` is a separate Python entry point using the existing offline
openpyxl/Pydantic/defusedxml stack. It reads only explicitly selected exported workbooks
and optional report evidence/guidance, never the analyzer, workspace, collector or database.
It preserves original worksheets, IDs, approvals, risk and path states; a new exact
40-column reader view refines evidence presentation only. Narrative suggestions and
material corrections live in supplemental views and an Assessor QA / Exceptions register.
No human approval or confirmed finding is created. New files leave source exports intact.
A report review copy remains possible with missing IAM, with explicit limitations.
