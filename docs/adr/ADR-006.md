# ADR-006: Recoverable scoped assessment lifecycle

Status: accepted for 0.5.1rc1. Existing DuckDB and modular monolith remain unchanged.

Replacement stages a temporary copy of the existing database, imports through the shared
bounded importer and performs full assessment/correlation. It publishes only after success,
retaining historical immutable snapshots and evidence-bound analyst approvals.

Deletion requires an exact provider/identifier, fresh preview token and separate explicit
confirmation. It stages scope removal and full reassessment, creates a compact logical
copy, then swaps the database using a recoverable journal and temporary checkpoint.
An OS lock complements the existing serialized API writer. Recovery runs before opening
the workspace. Only exact managed paths are removed; shared raw configurations spanning
scopes block permanent deletion. Source bytes are never rewritten.

This avoids partially replaced scopes and rollback-dependent conclusions. Temporary
staging consumes extra disk space and full reassessment takes time. This is neither a
second persistent database/service nor forensic erasure. External backups/exports remain
the operator's retention responsibility; completed journals/checkpoints are removed.
