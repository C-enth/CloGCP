## 3. Member role, trust policy and StackSet

- `collectors/aws/policies/member-role-stackset.cfn.json`: CloudFormation (JSON) template for a service-managed StackSet targeting the member OUs. Parameters: `RoleName`, `HubAccountId`, `HubPrincipalArn`, `OrganizationId`, `MaxSessionDuration` (default 3600). It attaches SecurityAudit and the supplement inline. Service-managed StackSets do not deploy to the management account; create the role there separately if the management account is in scope.
- `collectors/aws/policies/member-trust-policy.json`: the same trust as a standalone document. Replace `HUB_ACCOUNT_ID`, `HUB_PRINCIPAL_ARN` (for example `arn:aws:iam::<hub>:role/aws-reserved/sso.amazonaws.com/*/AWSReservedSSO_<set>_*` for an IAM Identity Center permission set) and `ORGANIZATION_ID`.
- The trust binds `aws:PrincipalOrgID`, so CloSec's own R1-IAM-ROLE-TRUST-CONDITIONS does not report the collection role as an unconditioned cross-account trust.

## 4. Hub (operator) permissions

`collectors/aws/policies/hub-operator-policy.json`, attached to the identity that runs the collector, the probe or the batch orchestrator:

- `sts:AssumeRole`: Assume the member read-only role in each approved account.
- `organizations:ListAccounts`: Optional: account search in the interactive collector (management or delegated administrator only).

## 5. Management account: Organizations, SCPs and RCPs

Organizations read APIs other than `DescribeOrganization` answer only in the management account or an Organizations delegated administrator; member-account collection receives AccessDenied, which the collector journals and the analyzer reports as "organization controls not assessed" (never as "no SCP"). For SCP and RCP content, run the collector once against the management account (or a delegated administrator) with these actions (`collectors/aws/policies/management-organizations-read-policy.json`; SecurityAudit already grants `organizations:Describe*` and `organizations:List*`):

- `organizations:DescribeOrganization`
- `organizations:ListRoots`
- `organizations:ListParents`
- `organizations:ListPoliciesForTarget`
- `organizations:DescribePolicy`
- `organizations:ListPolicies`
- `organizations:ListTargetsForPolicy`
- `organizations:ListAccounts`
- `organizations:DescribeAccount`

The collector records the organization ID and management account ID from `DescribeOrganization` (available to members) in the manifest, and states explicitly when organization policy access is missing.

## 6. Session duration

Recommended: **3600 s** (`DurationSeconds=3600`, role `MaxSessionDuration` 3600). When the hub identity is itself an assumed role (IAM Identity Center or another role), AWS limits the chained session to one hour regardless of `MaxSessionDuration`. The collector uses refreshable assume-role credentials and the batch orchestrator re-assumes before expiry, so longer sessions are not required; raise `MaxSessionDuration` only when the hub uses long-term credentials and the operator wants fewer AssumeRole calls.

## 7. Pre-flight probe coverage

`collectors/aws/preflight.py` makes 41 read-only calls per account (global families once, regional families per Region), all within SecurityAudit plus the supplement.

## 8. Not verified

- No real AWS account was used. Coverage is computed from the policy snapshot, not from an IAM policy simulation; SCPs, permission boundaries and service opt-in can still deny an allowed action (the probe reports that per account).
- IAM action names come from the Service Authorization Reference naming; the table `ACTION` in the generator lists every name that differs from the API operation.
